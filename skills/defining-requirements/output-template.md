## 5. 비기능 요구 (NFR)
- 정합성 / 동시성 / 멱등성 / 성능(P95·부하) / 가용성 / 관측성 / 감사 — 해당 항목만, 각 한 줄.
- **관측 수단 (질문이 아니라 산출물로)**: 이 피처의 실패를 *유저 제보보다 먼저* 알려줄 메트릭/알람 이름 + 채널(프로필 `observability` 에서). 없으면 "계측 추가"가 §4 범위에 들어간다 — "관측성 필요함" 한 줄로 끝내면 그건 챙긴 게 아니다.
  - 사후 추적(CS·장애 원인 규명)에 필요한 기록이 남는 지점 + 이어 붙일 키(상관관계 id·주문번호 등)도 여기 한 줄. 남기지 않기로 했으면 "사후 추적 불가 — 재현으로 대체" 처럼 *결과*를 명시한다 (안 적으면 §6 AC 가 검증 불가능한 걸 검증 가능하다고 적는다).
- **부하테스트 판정 (게이트 — 생략 금지)**: 필요/불필요 + 걸린 신호 + (필요 시) 측정 수치(P95·RPS 목표).
  - 신호: 새 hot path · 요청 증폭(fan-out) · 직렬화 지점 추가(락/트랜잭션) · 동기 외부 의존 추가 · unbounded 데이터 쿼리 · capacity 임계 근접 · 스파이크 예정.
  - 판정 입력은 추측 트래픽이 아니라 **실측**(현재 메트릭)과 프로필 `capacity` 대조. '필요'면 수행은 라이프사이클 10.5(프로젝트 몫).
