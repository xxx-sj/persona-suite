## 2. 모듈 / 책임 경계
- 새 로직 위치: <기존 모듈 vs 새 모듈 + 이유>
- 책임(SRP): <각 클래스/서비스가 하는 일 한 줄>

## 3. 패턴 / 추상화
- 선택: <인터페이스/전략/단순 함수 …>
- 대안 비교 + 왜: <...>
- YAGNI 근거: <2회+ 반복이라 추상화 / 1회성이라 단순>

## 4. 에러 처리 + 기록 구조
- throw/catch 위치, 에러 종류, 관찰 가능한 결과(거부·롤백 등)
- 기록 위치: <어느 계층에서 남기나 · 레벨 · 요청을 잇는 키 · 마스킹 대상 — 프로필 `observability.로깅 규약` 준수 여부. 규약이 없으면 여기서 정한 걸 프로필로 승격>
- 삼킴 점검: <catch 후 기록만 하고 정상 응답으로 빠지는 경로가 없나 / 같은 에러가 계층마다 중복 기록되지 않나>

## 5. 보안 / 정합성
- 입력 검증 위치 · 권한 체크 위치 · 트랜잭션 경계 · 민감정보 누출 점검

## 6. 테스트 용이성
- seam/DI, 부수효과(시간·랜덤·IO) 분리, 단위 테스트 가능 지점

## 7. 한계 / 트레이드오프
- <이 구조로 못 막는 것>
- **스케일 경로 (무거움 tier 의무 · 중간 이하 생략 가능)**: 트리거 <관측 지점 + 임계> → 깨지는 방식 <무엇이 먼저 무너지나> → 진화 <갈 구조 + 코드의 어느 지점이 바뀌나(경계 이동·추상화 도입·비동기 분리 등)>. **지금 구현하지 않는다** — 예약이지 착수 지시가 아니다 (YAGNI 와 충돌하지 않는 지점: 지금 코드는 최단순으로 두고, *언제 다시 열지*만 적는다). 학습 모드로 후보를 비교했으면 기각 후보 이름 + 사유 한 줄만 (비교 과정은 대화에 — PRINCIPLES §3).
